# NADO ПРАЗДНИК

Собственная рабочая кодовая база платформы создания и управления мероприятиями.

## Статус

Текущая версия создана из донорской сборки `nado-праздник (14)` и переводится на контролируемую архитектуру. Донор используется как источник интерфейсов и части моделей, но не считается готовым production-приложением.

## Ближайшая цель

Стабилизировать `NADO CONTRACTS`, получить зелёные TypeScript, unit и e2e проверки, затем перейти к CRM заявок, SLA ответа и календарю доступности.

## Команды

npm ci

## Ограничения текущего прототипа

- нет реальных платежей;
- нет реальной электронной подписи;
- нет фактической юридической проверки;
- demo-подтверждения не являются электронной подписью;
- demo wallet не хранит деньги.
- MAX и Госуслуги в production заблокированы до подключения реального OAuth;
- Telegram в production принимает только подписанный `initData` и требует `TELEGRAM_BOT_TOKEN`;
- файловая база авторизации и память процесса предназначены только для локальной разработки;
- реальные денежные решения требуют отдельного подтверждения сотрудником, который не создавал это решение.

## Операционный контур

- центр владельца с обзором рекламаций, безопасности, ролей, договоров, скоринга и аудита;
- роли `owner`, `senior_operator`, `reclamation_manager`, `security_manager`, `read_only_auditor`;
- обязательная проверка фактов до решения по рекламации;
- компенсация ограничена стоимостью заказа;
- SAFETY и FRAUD получают критический SLA 30 минут;
- FRAUD автоматически создаёт запрос операционной блокировки;
- история действий по делу дополняется новыми записями и не редактируется через интерфейс.
